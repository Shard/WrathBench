## Ladder scatter — cost per run against xp earned

Operator's request: a point chart on the ladder, x the average cost per task for
the selected episode, y the XP earned, above the table; drop `all`, overridden
and the harness filter from the ladder; drop the filter-note text; point the
episodes page's filtering at the ladder rather than runs.

What "task" and "XP earned" mean, since neither is on the wire as such:

- **x = mean cost per run** over the entry's counted (scored, series-filtered,
  character-filtered) runs on the tier. A run's cost is the provider's reported
  figure when it reported one, else `CostView.expected` — the price table over
  the run's own tokens, which is $0 for a free tier or local hardware and
  as-if-metered for a subscription. The runs table deliberately shows only the
  reported figure; the chart takes the fallback because a free model has no
  reported figure ever and its honest cost is zero, not blank. The point's hover
  says which basis fed it and over how many of its runs.
- **y = mean XP earned** over the same runs, where a run's XP earned is the
  viewer's new `xpEarned`: the run page's cumulative-chart lower bound (last
  observed within-level xp of every level below, plus the xp within the top
  one), computed server-side so the two cannot disagree.
- One point per `(model, effort)` — `sonnet (low)` is its own point — because
  effort is a roster dimension. Unscored runs never enter. An entry with no
  reading on either axis is named under the chart, never plotted at zero.
- Linear axes with 1/2/5 ticks from zero; free models sit on the y axis. Labels
  are placed greedily around eight slots per point. Points are coloured by
  harness with the table's own semantics (`--accent` wrathbench, `--claude`
  claude-code, `--dim` mixed) and link to `/runs?model=…&effort=…&episode=…`.

Where it lives: maths in `dashboard/src/lib/ladder.ts` (`ladderPoints`,
`niceTicks`, `ladderChartLayout`, `runCostReading`, `xpEarnedOf`) with tests in
`dashboard/test/ladder.test.ts`; the SVG in
`dashboard/src/components/LadderChart.tsx`, hand-drawn like `XpChart`.

Viewer: `ResultRun` gained optional `xpEarned` and `expectedCost`
(`runner/viewer/api-types.ts`, `results.ts` `xpEarned()`, `api.ts`
`listingFacts`). Optional so a dashboard against an older viewer still works;
the chart then says the viewer predates `xpEarned` and needs a restart. **The
8090 viewer was not restarted and needs one to serve the fields**; the render
check ran against a second viewer on 8091 from this checkout, since stopped.

Removed: `EpisodePicker`, `HarnessPicker` and `EpisodeFilterNote` from
`dashboard/src/components/EpisodePicker.tsx` (only `HarnessTag` remains there),
`harnessParam`/`HARNESS_CHOICES` and the `all` choice from `lib/episodes.ts`,
and the `includeOverrides`/`harness` arguments of `api.ladder`. The shell-wide
series selector (ADR-0046) and its note stay: that is the comparability group,
not the loop tag. `/api/ladder` still accepts the old query parameters; nothing
in the dashboard sends them.

Episodes page: the tier id and the member count link to
`/ladder?episode=<id>`; the overridden count links to `/runs?episode=<id>`
because the ladder has no overridden view any more.

A Solid detail worth remembering: a `<For>` template rooted at `<a>` inside an
`<svg>` is created in the HTML namespace and paints nothing; rooting it at
`<g>` puts the subtree in the SVG namespace.

## Consolidation after the ladder chart

A pass over the ladder-scatter commit above, looking for what it left behind.

`niceTicks` and the linear value→pixel map (`px`/`py`) were each hand-written
twice: once inside `lib/ladder.ts`'s `ladderChartLayout`, and again inline in
`LadderChart.tsx` (for the gridlines, since the layout did not expose the same
scale it placed points with) and in `XpChart.tsx`. Pulled both into
`dashboard/src/lib/chart.ts` (`scaleLinear`, `niceTicks`), with its own tests
in `dashboard/test/chart.test.ts`; `LadderChartLayout` now returns the `px`/`py`
it built its points with, so `LadderChart.tsx`'s gridlines use the same scale
rather than recomputing it. The substitution is bit-identical arithmetic (an
exact IEEE754 negation, `(x-0)/span` reducing to `x/span`), pinned by the
existing `ladderChartLayout` tests, which still pass unchanged.

`EpisodePicker.tsx` renamed to `HarnessTag.tsx` — it has exported only
`HarnessTag` since the commit above; the four importers (`Models.tsx`,
`Ladder.tsx`, `RunDetail.tsx`, `Runs.tsx`) now name it. `lib/episodes.ts` had
no dead exports left to remove; `harnessParam`/`HARNESS_CHOICES`/`all` were
already fully gone; its test file has none of them either.

Checked but left alone: `ResultRun.xpEarned`/`expectedCost` (`results.ts`)
already have exactly one dashboard consumer each (`lib/ladder.ts`'s
`xpEarnedOf`/`runCostReading`, both reading the server field with a documented
viewer-predates-the-field fallback) — there was no local scalar recomputation
in `RunDetail.tsx` to replace. `runview.ts`'s `xpChartModel` is not a
duplicate of `results.ts`'s `xpEarned()`: the run page's chart needs the whole
reconstructed curve and its level bands, the ladder needs only the final
total, and the two are already independently tested against matching
fixtures/rules. A literal one-test cross-check (import `xpEarned` into a
dashboard test) was tried and reverted: it pulls `runner/viewer/tail.ts` →
`runner/src/context.ts` → `runner/src/sandbox/host.ts` into the dashboard's
`tsconfig.json`, which fails two of that file's checks under the dashboard's
settings though it is clean under the runner's own — a project-boundary
fight not worth forcing for one assertion. The "Not plotted" wording and the
`<a>`/`<g>` namespace comment in `LadderChart.tsx` were checked and are
unaffected by the removal — left as is. `ADR-0046`'s `EpisodeFilterNote`
mention is a separate, pre-existing rename (the component is `SeriesFilterNote`
now) unrelated to this pass; not touched.

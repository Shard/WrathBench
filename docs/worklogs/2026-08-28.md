# 2026-08-28

## The free-billing allowlist outlived its one entry

`FREE_SUFFIXLESS_ALLOWLIST` existed for one id: `stealth/ox-alpha`, a stealth model OpenRouter listed at 0/0 for its preview window (verified 2026-08-22). That window ran to about 2026-08-26 and the model has since been revealed as ZAI GLM-5.3-Flash, priced like any other paid model. The allowlist entry outlived it, so the harness was classifying a paid model as free on both sides of the split: `billingOf` would schedule it on the free account pool and let it spend none of the paid concurrency budget, and `runBilling` would read its runs as costing nothing.

The set is empty now, and empty is its resting state — it is an escape hatch for an id that is genuinely 0/0 and wanted on the free pool, not a list anything accumulates on. The export stays, because the fleet's roster policy reads the same set and because the extension point is the documented way back in; the doc comment now says why it is empty and what would justify an entry.

Nothing else needed a code change: `isAllowlistedFree` is a `Set.has`, every caller (`billingOf`, `runBilling`, `priceFor`, `validateEntries`) already handles a miss, and an empty `Set<string>` types fine once it is spelled with the argument.

What did need changing is the tests, and the interesting part is how. Several fleet fixtures used `stealth/ox-alpha` as *an example of a free model*, not as an example of an allowlisted one — the allowlist was incidental. Those move to `stealth/ox-alpha:free`, which is free by suffix and so no longer depends on mutable operator state; `slug()` strips `:free`, so every run-id assertion (`fleet-ox-long-ox-alpha-20260101`) and every account-class count survives unchanged. The tests that were really about the allowlist keep testing the mechanism rather than the retired id: an unknown suffixless id is paid and is refused by the roster policy, `FREE_SUFFIXLESS_ALLOWLIST.size` is asserted to be 0 so a re-add is a deliberate edit rather than drift, and each assertion that used to name the id now loops over the set — vacuous today, correct the moment anything is added.

Two assertions flipped from free to paid, and they are the behaviour change: `runBilling({model: "stealth/ox-alpha"})` and `billingOf({model: "stealth/ox-alpha"})`. In scheduling terms that id, if it were ever put back in the roster, would now take a paid-class account and count against `policy.paid`'s cap instead of running free on the pool.

The synced price table did not follow the same day: `runner/viewer/prices.openrouter.json` still reads 0/0 for the id, so the viewer prices those runs at nothing. That is item 88.

## Roster refresh: three dead slugs out, GLM Flash 5.3 in under its own name

The fleet had run itself dry — `--status` read `nothing schedulable`, with six free
lanes tainted since the 2026-08-25 endpoint outage and every remaining entry either
at its target or retired. The refresh was mostly a question of which of those lanes
were still real.

Three were not. `stealth/ox-alpha` was revealed as ZAI GLM-5.3-Flash and its stealth
free window closed (the billing half of that is above, and item 88). `x-preview-f-free`
and `laguna-s-2.1-free` are both absent from OpenCode Zen's current catalogue, which
is the likelier reading of `x-preview-f`'s 503 storm than the rate-limiting it was
first attributed to. All three entries are gone from the roster. Deleting an entry
does not hide its runs — `listRuns` enumerates directories off disk and never joins
against the roster, and `models.ts` says so outright ("a completed campaign's results
outlive the deletion of its entry") — so the corpus is intact and only new scheduling
stops. Leaving them in place was the alternative, and it is worse: their targets are
met today, but a harness minor bump re-arms scored targets and would send fresh
attempts at three endpoints that no longer exist.

GLM Flash 5.3 goes in as `glm-53-flash`, its own entry rather than a repoint of
`ox-alpha`. A repoint would have been cheaper and would have inherited three runs of
evidence, but those runs were collected against a stealth endpoint on bad uptime and
attributing them to the named model would be a quiet lie about what was measured. It
enters at t1 rather than the usual t0 trial for the same reason: t0 buys one episode,
which is *less* evidence than ox-alpha got, so a t0 trial could not settle the
question the fair re-run exists to answer. Three e90 runs at $0.075/$0.25 per Mtok is
a rounding error against the answer.

Promotions: `gemini-flash` t0 to t1 (the only paid trial with two consistent runs, L5
clean and L4 stalled) and `sub-haiku` t0 to t1, which promoted straight to t2 on the
witness it already held — the cheapest model in the field matched every full-price
sonnet and opus effort variant at L6 on its single run, and that is worth three more
episodes to confirm or kill.

The five tainted lanes whose slugs verify live were cleared (`muse-spark`, `hy3`,
`nemotron-ultra`, `north-mini-code`, `laguna-or`). Order matters here: `--clear-model`
on a still-dead endpoint burns three fresh attempts and climbs the defer ladder, which
is how `nemotron-nano` retired at 10, so every slug was checked upstream first.

`nemotron-super` gets `idle: "unlimited"` — the first free lane to take the freeplay
fallback. The concern was that a freeplay session with no wall clock would starve the
scored runs, and the pause records answer it: OpenRouter's free tier is one
account-wide daily bucket (`limit_source: openrouter_free_tier_daily`, limit 1000,
keyed to the user), so freeplay does compete. But `idle` only fires once a model's
tier is spent, and with the fleet reporting nothing schedulable that bucket was
expiring unused every day. One lane, on the healthiest free endpoint (99.69% provider
uptime), is the scoped version of that bet. The throttle that actually leaves tokens
unused turns out to be `policy.maxConcurrent.openrouter: 1`, not the daily cap —
raising it is a separate call, and against it is that a mid-run 429 on a scored run is
unrecoverable, since scored lanes never resume.

shipped: item 87 — class-probe now sets `resume: true` and `maxAttemptsPerCell: 3`,
and the roster half of the same item is settled: the two dead campaign models are
retired and `nemotron-super` took the idle axis instead. The attempt cap could finally
go in the file because the supervisor is a bind-mount of the working tree and was
restarted after c2eae8e, so the strict-schema rejection that held it out is gone.

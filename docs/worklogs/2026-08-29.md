## Guaranteed hint delivery: the harness carries its own message home

The delivery track for the principle recorded above. The SDK's recovery hints were only ever readable if the snippet kept the result object, so a11's `.status`-only loops threw 41 of them away. Now `WrathClient` also tallies every hint-bearing failure — the four `MOVE_HINTS` paths plus `unknown_target` and the failed `transferred` / `teleported` verdicts — per `(action, status)`: count, the last occurrence's hint and destination point, ts. Aggregated rather than logged per occurrence because the recipes interpolate coordinates, so 41 `too_far` hints are 41 distinct strings that say one thing; the last one is kept because it is the one nearest where the character now stands. Only the status recipe is recorded, not the per-call budget/timeout notes `withNotes` folds in — those are already in the result and would vary every call.

The sandbox child drains the tally onto each eval result (onto the pong for an abandoned eval, the way logs already ride it), the host hands it up as `SnippetResult.actionHints`, and `tools.ts` renders it at the foot of the snippet result:

```
--- harness ---
moveTo too_far ×21: (-6048, 367) is 312y away in a straight line; a single moveTo covers ~250y. Walk to an intermediate point first.
```

One line per status, count only when it repeats, hint text unchanged, at most four groups and 320 chars each with a `(+N other failure statuses)` tail. It goes in the tool result, not the turn's harness-notice block: a claude-code turn is a whole CLI session, so a notice there would land a turn late — the follow-up inspection the principle rules out. Both drivers dispatch through the same `callTool`, so both get it identically, and the trajectory already logs the rendered text as `snippet_result` / `tool_result` — no new record type, no notice-kind sweep. It renders on successful snippets too, which is the main case: a11's snippets all returned `ok`.

`drainActionHints` is listed internal in the API-docs generator, so nothing new appears in the model-visible `sdk/API.md`. Tests are fixture-based: the client tally and its once-only drain against the SDK stub server, the IPC path against the real sandbox child, and the render's grouping/count/cap/truncation plus a `callTool` case where the snippet returned only statuses. No live check — a11 is still running on RUNNER2 and the recorded statuses plus fixtures cover the path. Harness version deliberately untouched.

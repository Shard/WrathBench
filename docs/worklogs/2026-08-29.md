## Guaranteed hint delivery: the harness carries its own message home

The delivery track for the principle recorded above. The SDK's recovery hints were only ever readable if the snippet kept the result object, so a11's `.status`-only loops threw 41 of them away. Now `WrathClient` also tallies every hint-bearing failure — the four `MOVE_HINTS` paths plus `unknown_target` and the failed `transferred` / `teleported` verdicts — per `(action, status)`: count, the last occurrence's hint and destination point, ts. Aggregated rather than logged per occurrence because the recipes interpolate coordinates, so 41 `too_far` hints are 41 distinct strings that say one thing; the last one is kept because it is the one nearest where the character now stands. Only the status recipe is recorded, not the per-call budget/timeout notes `withNotes` folds in — those are already in the result and would vary every call.

The sandbox child drains the tally onto each eval result (onto the pong for an abandoned eval, the way logs already ride it), the host hands it up as `SnippetResult.actionHints`, and `tools.ts` renders it at the foot of the snippet result:

```
--- harness ---
moveTo too_far ×21: (-6048, 367) is 312y away in a straight line; a single moveTo covers ~250y. Walk to an intermediate point first.
```

One line per status, most recent first, count only when it repeats, hint text unchanged, at most four groups and 320 chars each with a `(+N other failure statuses)` tail. Nothing is reactive: the count is the collapse marker for repeats of one hint and no ordering, rendering or phrasing decision reads it — no thresholds, no escalation, no harness-authored advice (operator constraint, Mark, 2026-08-29). It goes in the tool result, not the turn's harness-notice block: a claude-code turn is a whole CLI session, so a notice there would land a turn late — the follow-up inspection the principle rules out. Both drivers dispatch through the same `callTool`, so both get it identically, and the trajectory already logs the rendered text as `snippet_result` / `tool_result` — no new record type, no notice-kind sweep. It renders on successful snippets too, which is the main case: a11's snippets all returned `ok`.

`drainActionHints` is listed internal in the API-docs generator, so nothing new appears in the model-visible `sdk/API.md` (regenerated: byte-identical), and it is deliberately not re-exported from the SDK package entry point — that surface is part of the harness version, which this change does not bump. A snippet that went looking could still call `sdk.drainActionHints()` and swallow its own block; undiscoverable and accepted, not worth code. Tests are fixture-based: the client tally and its once-only drain against the SDK stub server, the IPC path against the real sandbox child, and the render's grouping/count/cap/truncation plus a `callTool` case where the snippet returned only statuses. No live check — a11 is still running on RUNNER2 and the recorded statuses plus fixtures cover the path. Harness version deliberately untouched.

shipped: guaranteed hint delivery — sdk/src/client.ts (tally + drain), runner/src/sandbox/{ipc,entry,host}.ts (channel), runner/src/tools.ts (`renderActionHints`), docs/ARCHITECTURE.md (why)

## Item 88 settled: a delisted model reads as delisted, not as free

`stealth/ox-alpha` held a 0/0/0/0 row in `prices.openrouter.json` by hand. That row was
reached — the id has no `:free` suffix, so `priceFor` fell through to the synced table
and rendered `basis: "list-price"`, `priceId: stealth/ox-alpha`, "$0.00", noted as an
OpenRouter list price metered against the operator's balance. All 22 runs on the id read
as a paid model that cost nothing, which is the one reading a cost column must never
produce, and it is what an outside reviewer would have seen this weekend.

Of item 88's three options the blank is the one that ships. The windowed-free version
was tempting — those runs really were free while the preview window was open — but the
worklog dates that window's end as "about 2026-08-26", and a boundary the repo describes
as *about* is a guess; `pricing.ts` opens by saying a guessed price is worse than a
blank. Nothing true is lost: `usage.cost` is present and zero on those runs' responses,
so the actual column still reads a sourced $0.00 with the provider behind it, and only
the expected column goes blank.

The row is deleted, and the other half of the fix is `unpricedNote`, which used to tell
every unpriced non-Claude model to run `sync-prices`. For a delisted id that instruction
is false — the sync is what *drops* the row. `DELISTED_MODELS` in `runner/viewer/pricing.ts`
now names the id and why, and is both the note the reader sees and the record of why the
row is absent from a file whose whole point is that nobody types rates into it. The PIN
in `infra/sync-prices.ts` stays, as the standing ask should the id ever be relisted.

Two tests generalise the one-time grep. Every 0/0 row in the synced table must be a
`:free`/`-free` slug — those are answered by rule before the table is consulted, so a
suffixless zero is by construction a paid model whose price went missing, and the next
stealth id trips this automatically. And every `DELISTED_MODELS` id must be absent from
the table, so the note and a row cannot both claim to be right. Swept the corpus for
others: `stealth/ox-alpha` was the only one. The remaining five zero rows are all
`:free`-suffixed and never read.

`bun test` 2316 pass / 0 fail and `bun run typecheck` clean, both before and after.

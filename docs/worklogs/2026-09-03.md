# 2026-09-03

Two new releases added to the roster at t0 on Mark's ask: Google's Gemini 3.8 Flash
and Meta's Muse Spark 1.3.

## Roster additions

- `gemini-38-flash` — `google/gemini-3.8-flash` on OpenRouter, paid ($0.75/$3.75 per
  Mtok, same list as 3.7), t0. The 3.7 entry stays at t1>t2 untouched; a new version is
  a new model, never an edit to an existing entry's slug.
- `muse-spark-13` — `meta/muse-spark-1.3-contributor` on OpenRouter, t0. The cheap
  option: $0.10/$0.20 per Mtok against $1.25/$4.25 for the plain slug, on the same
  contributor terms as the OpenCode slug the 1.2 entry uses (the provider keeps prompts
  and completions; accepted trade, see the free-model data note). It carries no
  `-free` suffix so `billingOf` derives paid and it lands on SHAKEOUT2, which is what
  we want: it is metered.
- Why OpenRouter for Spark and not OpenCode's `muse-spark-1.3-contributor-free`:
  OpenCode returned `Internal server error` for both the 1.3 and the 1.2 contributor
  slugs on probe, and the live board shows the existing `muse-spark` entry tainted (3
  failed attempts, 6 stillborns). The endpoint is down, not the model.
- Both slugs were probed with a one-shot tool call before adding; both tool-called
  correctly. Gemini 3.8 spent its whole 60-token budget on reasoning on the first
  probe and only tool-called with room to think, which is worth knowing when its e90
  is read.
- The supervisor hot-loaded the file within the minute: `gemini-38-flash` was on
  SHAKEOUT2 at L2 seven minutes in; `muse-spark-13` is queued behind it (one paid in
  flight).

## Price sync

`bun infra/sync-prices.ts` priced both new ids and, as a side effect, appended
2026-09-02 rate windows for five ids whose OpenRouter list price moved since the
2026-08-28 sync (deepseek-v4-flash, -flash-0731, -pro-0813, gemini-3.7-flash,
qwen3.8-27b; all cheaper). Earlier runs keep their old rate by construction.

That broke one test: the doubling test in `runner/test/viewer-pricing.test.ts` asserted
every id ends the sync with exactly two windows, which assumed the real file had one
window per id. It now expects one more than the id already had. The test reads the
real price file, so it would have broken on the first genuine rate change regardless.

## Slip

A `git stash` on the two edited files ran for about five seconds during test
triage, against the standing no-stash rule in memory. Popped at once; the running
Gemini job was checked afterwards and was not drained (the supervisor reloads every
60s and did not see the window).

## Promotion

`muse-spark-13` reached level 5 on its t0 e90 — the `t0*` witness — so Mark called it
promoted at that price and it moved to t1 by hand (`tier: "t1"`). It climbed straight
to t1>t2 on the evidence it already had, per the rule: a t0 model that earns rung 1
promotes immediately on a manual tier bump, nothing re-run.

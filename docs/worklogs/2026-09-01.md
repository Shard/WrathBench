## Issue #41: `edit_scratchpad`

**Research (what the reference harnesses do).** Claude Code's `Edit` is the
model: `old_string` / `new_string` with optional `replace_all`; `old_string`
must match byte for byte, whitespace included, and be unique in the file, or
the call is refused with "not found" / "matched N times — include more
surrounding context"; `old_string === new_string` is refused; the file must
have been read first. Full replacement stays a separate `Write` tool. Aider
takes the same shape as a prose SEARCH/REPLACE block parsed out of the reply,
and its notes files are append-only. What fits here: the exact-match,
refuse-on-ambiguity contract — it is the referent discipline the SDK already
uses, it is deterministic, and every model is trained on some spelling of it.
What does not: Aider's parse-from-prose channel (we have real tool calls), a
line-range edit (line numbers are state the model does not reliably hold), and
the "read the file first" precondition — the pad is injected verbatim into
every turn's context, so it is met by construction. No convenience tier: an
edit and a full rewrite are two operations, not a helper over one.

**What shipped.** `Scratchpad.edit(old, new, replaceAll)` in
`runner/src/scratchpad.ts` returns a discriminated result and decides
everything semantic: `empty_old`, `identical`, `not_found`, `ambiguous` with
the match count, else the replacement, routed through `write()` so the 32,000
char cap and its truncation marker are inherited unchanged. Plain string
operations throughout (`split`/`join`, `indexOf`) — `old` and `new` are model
text, so a RegExp would choke on metacharacters and `String.replace` would
interpret `$&` in the replacement. `edit_scratchpad` in `runner/src/tools.ts`
is the ninth tool: Zod-validated `{ old: string, new: string, replaceAll?:
boolean }` (strict, `replaceAll` through the existing `booleanish`), the
Claude-Code-shaped argument names repaired as aliases
(`old_string`/`oldString`/`old_text`/`search`, the `new_*` equivalents,
`replace_all`), each refusal rendered as a per-failed-call hint saying what to
fix and never what to play, and a short success line
(`edited (1 replacement; N chars, M lines)`) rather than an echo of the pad —
the pad is re-injected next turn anyway. `write_scratchpad` is untouched.
Dispatch is the shared `callTool`, so both drivers get it and the trajectory
records it as an ordinary `tool_call`.

Sweep: the prompt's scratchpad bullet (`runner/src/prompt.ts`) now says which
tool is for which, `docs/ARCHITECTURE.md`, `runner/README.md`,
`runner/src/adapter-claude.ts`, `runner/test/claude-driver.test.ts` and
`runner/viewer/tools.ts` went from eight tools to nine, and `/api/tools`
carries an `edit_scratchpad` example.

The decision is recorded in `docs/METHODOLOGY.md`, "The model surface" —
operator decision 2026-09-01, on the #41 evidence table (~28% of a
high-frequency writer's rewrites changed under 20% of the pad). The count
sentence in "Context policy" went eight → nine as a factual correction; no
